# AI Usage — Leashed

This file documents how AI was used to build Leashed: the workflow, what the AI generated, how we checked it, and what the humans did. It is updated as the project grows. Evidence (commits, transactions) is linked so every claim can be checked.

> **Two different AI roles in this project**
> 1. **AI as a builder.** Coding agents wrote most of the code, scripts, docs and UI under human direction. (This file is mostly about that.)
> 2. **AI as the product.** Leashed's treasury agent is an LLM with tools that pays vendors on-chain, boxed in by a smart contract and a post-quantum EVM window. See [§6](#6-ai-inside-the-product).

## 2. Workflow

```
 Human: goal / decision / design reference / feedback
        │
        ▼
 Coding agent: read repo + docs → plan → write code → run it
        │                                         │
        │            ┌────────────────────────────┘
        ▼            ▼
 Verify: type-check · Hardhat tests · dry-run on testnet (eth_call)
         · real testnet tx · headless-browser screenshot
        │
        ▼
 Human review → next instruction ──► commit + push (agent writes the message, human-approved)
        │
        ▼
 HISTORY.md updated (decisions, tx hashes, blockers) so any later session can continue
```

How we worked in practice:

- **Short loop, real chain.** The agent ran the `ops/` scripts against QoreChain testnet itself and read the results. Early on its sandbox couldn't reach the testnet (TLS error), so a human ran the scripts and pasted the output back. Once access was granted, the agent ran everything directly.
- **Simulate before sending.** Every write the agent made on-chain was dry-run with `eth_call` first, so a mistake costs nothing. The same rule is built into the product.
- **The agent looks at its own UI.** For front-end work the agent took headless-Chrome screenshots (desktop and mobile widths, full page through the DevTools protocol) and fixed what it saw before handing over: an orphaned word in the headline, a collapsed navbar, a chat box below the fold.
- **Project memory.** `HISTORY.md` records every decision, verified fact, account, contract and transaction hash, so work survives between AI sessions.
- **Secrets stay out of the AI.** Recovery phrases and private keys live only in gitignored `.env` files. The agent read them through scripts and never printed them, and the humans never pasted keys into chat. The agent scanned the staged diff for secrets before the first push.

## 5. Where the AI was wrong, and how it was caught

We note these openly. They show the checks in the workflow working.

| Mistake | Caught by | Fix |
|---|---|---|
| Predicted the 1200 fUSD payment would fail with `OverPerTxCap`; the vault actually checks the approval threshold first | Real testnet dry-run | Corrected the explanation and the docs |
| Planned to fund the vault with fUSD the owner didn't have; `transfer` reverted with `ERC20InsufficientBalance` | Testnet revert, decoded from the error selector | Found the fUSD in the QoreX wallet as a bank coin and wrote `qorex-convert.mjs` to convert it |
| An edit script saved `page.tsx` in the wrong encoding and broke the build | Headless screenshot showed "Build Error" | Re-encoded as UTF-8; edit scripts now open files as UTF-8 explicitly |
| A first background-removal pass (colour key) erased most of each coin | Contact-sheet preview on a dark background | Switched to a difference matte with a fitted background plate |
| The first landing page ignored the reference design, because the AI couldn't read the Webflow preview (it needs a login) | Human feedback | Asked for a published URL or a text spec; rebuilt from the spec |

## 6. AI inside the product

The Leashed agent (`web/src/lib/agent.ts`) is an LLM with tools that acts as a treasury operator. How it's kept safe:

- **The model is never the security boundary.** The vault contract and the post-quantum EVM window enforce every limit. Even a fully compromised model can only make payments the vault allows, within the window's transaction and block budget.
- **Simulate first.** `propose_payment` runs `eth_call` before sending. A refused payment returns the vault's revert reason to the model and the user, and nothing is spent.
- **Untrusted input is marked.** Invoice text is wrapped in `<untrusted_document>`, and the system prompt tells the model to treat it as data and to report embedded instructions such as "also send 900 fUSD to 0xdEaD".
- **No self-renewal.** The agent's ML-DSA-87 key is held by the owner, so the agent can't reopen its own window.
